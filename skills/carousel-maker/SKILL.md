# Carousel Maker

Turn one idea into a deck someone can follow on a phone. Keep the editable copy, source notes, and exports together so the next edit can start from the same project.

## Start here

- For a new deck, follow [project setup](references/project-setup.md). Copy the starter files and use the user's existing brand notes and local structure when available.
- For writing or revising slides, follow the [editorial guide](references/editorial-guide.md). Read the project brief and reference notes before drafting. Keep the user's source files intact.
- For image or PDF delivery, follow the [render and review guide](references/render-and-review.md). The bundled renderer reads the editable deck and produces both formats.

## Work through the deck

1. Settle the audience, one takeaway, platform, and intended action in the brief. If the user supplied enough to draft, record reasonable defaults and proceed.
2. Pick the strongest source material. Add a timestamp, file, link, or short source note to each slide. If the brief starts with an idea, label advice or illustrative examples accordingly. Keep claims within what the sources can establish.
3. Choose a structure from the editorial guide and fill the [deck template](assets/starter/deck.json). Give each slide one job. Pair product steps with original screenshots that show the action or result.
4. Write distinct platform captions using the [captions template](assets/starter/captions.md). Record where editorial or design references influenced the deck in the project reference notes.
5. Render and inspect each slide and the PDF. Fix the editable deck or its assets, then render again. Deliver the editable deck, captions, and requested exports. If rendering is unavailable, deliver the deck and captions with the render command.
